# Прошивка E18 (CC2530) через ESP8266 (Wemos/Lolin D1 mini)

Проверено 2026-10-01 на плате DIYRuZ Geiger с модулем E18-MS1PA1-PCB (заводской, заблокированный).

## Подключение (разъём J1 на плате, подписи на нижнем слое; квадратная площадка = GND)

| J1         | D1 mini |
|------------|---------|
| GND        | G       |
| P2.1 (DD)  | D5      |
| P2.2 (DC)  | D2      |
| RST        | D1      |
| VCC        | не подключать — плата питается от своего USB |

Питать плату от 3V3 D1 mini можно, но импульсный преобразователь ВВ даёт помехи на общей
шине 3,3 В: в таком режиме запись срывалась. Трубки на время прошивки вынуть.

## Программатор

[CCLib](https://github.com/kirovilya/CCLib) (форк с поддержкой ESP8266), пример `Arduino/CCLib/Examples/CCLib_proxy`,
`platformio.ini` уже есть (`env:d1_mini`). Наложить `CCLib_proxy-d1mini.patch`:

- DD на одном выводе D5 (у ESP 3,3 В, делитель не нужен; библиотека сама переключает направление);
- Wi-Fi выключен (меньше пиков тока);
- `Serial.setRxBufferSize(4096)` — **обязательно**: штатный буфер 256 байт, пакеты по 2 КБ теряются,
  и запись обрывается с «Could not read from the serial port»;
- 115200 бод (страница 2 КБ ≈ 0,2 с вместо 2 с).

`pio run -t upload --upload-port COMx`

## Python-часть

Python 3 + `pyserial`. CCLib написан под Python 2 — наложить `cclib-python3.patch` на `Python/cclib/ccproxy.py`
(bytes вместо chr/ord, 115200 бод, ожидание загрузки ESP 4 с).

Из HEX релиза удалить запись типа 05 (CCLib её не понимает):

    grep -v "^:04000005" DIYRuZ_Geiger.hex > DIYRuZ_Geiger_cclib.hex

Скопировать `auto_flash.py` (и при необходимости `flash_e18.py`, `resume_e18.py`) в `CCLib/Python/`.

Проверка связи:

    python cc_info.py -p COM3
    # заводской модуль: Flash size 16 Kb, [X] DEBUG_LOCKED — это нормально, после стирания будет 256 Kb

Основной способ — `auto_flash.py`: ждёт появления D1 mini (CH340), стирает чип, переподключается и пишет
постранично (2 КБ) со стиранием и проверкой каждой страницы; при ошибке страница переписывается (до 3 раз),
при обрыве связи — переподключение.

    python auto_flash.py DIYRuZ_Geiger_cclib.hex
    # ... page 96/96  17.3 min
    # DONE: 96 pages written + verified

После прошивки отсоединить провода от J1 (особенно RST) и передёрнуть питание: прошивка этого форка
даёт две вспышки и два сигнала.

Запасные варианты: `flash_e18.py COM3 <hex>` (стирание + запись блоками), `resume_e18.py COM3 <hex> 0x22000`
(дозапись с адреса страницы без полного стирания).

## Что встречалось на практике

- «The chip is not responding» — нет питания платы или плохой контакт в J1 (провода просто вставлены в отверстия);
  поправить контакт, повторить `cc_info.py`.
- Отвал USB D1 mini посреди записи (`Access is denied`, порт пропал) — плохой кабель/порт; переподключить,
  запустить `auto_flash.py` заново (стирает и пишет с начала).
- Единичная «Flash verification error» на странице — скрипт сам перезаписывает страницу.
- Модуль может прийти не заблокированным и с чужой прошивкой (256 KB, без DEBUG_LOCKED) — шить так же.
- Под отладчиком CCLib (режим отладки по умолчанию приостанавливает таймеры) прерывания таймеров не
  обслуживаются — поведение таймеров/прерываний проверять обычным запуском, а не под отладчиком.

Время при 115200 бод: ~11 с на страницу 2 КБ с проверкой, ~17–19 мин на образ ~190 КБ.
